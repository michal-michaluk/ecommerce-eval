## Business Context

Order Fulfillment handles the post-checkout process: warehouse picking, packing, shipping, and delivery tracking. It integrates with the warehouse system for stock, locations, and reservations, and with delivery companies for parcel registration and tracking.

### Background
- Orders are immutable after checkout
- Warehouse employees assign themselves to orders (guarded — one at a time)
- Delivery numbers are obtained early from delivery company
- Warehouse provides an optimized pick list based on order items and warehouse layout
- Employee scans products during picking — system marks position as packed
- Employee marks order as ready for delivery — delivery company is notified
- Delivery company sends full tracking chain: registered → ready → assigned → picked up → sorting → delivery → customer received
- Short-term reservations during picking to avoid collisions
- Warehouse stock changes are reflected in real-time on pick list
- Issues (lost item, wrong location, damaged) put order on hold
- Issue dashboard for other personnel to resolve problems
- If stock is missing during fulfillment, order is adjusted manually (outside system)

### Key Goals
1. Efficient warehouse picking with optimized routes and collision prevention
2. Real-time delivery tracking for customers and operations
3. Handle warehouse issues gracefully without blocking the entire process
4. Ensure order integrity through pick+scan confirmations

### Stakeholders
- Warehouse Employee (pick, pack, ship)
- Issue Resolver (find missing items, correct location)
- Operations (track delivery state, manage issues)
- Customer (track order status)

## Actors & Interactions

### Warehouse Employee
- Views order list with status
- Assigns to order (guarded — exclusive)
- Receives pick list (optimized route)
- Reserves picked product (short-term)
- Scans product (pick confirmation)
- Marks position as packed
- Marks order as ready for delivery
- Reports issue (lost item, wrong location, damaged)
- Views current stock per location

### Issue Resolver
- Views issue dashboard
- Sees orders on hold
- Searches for missing items
- Corrects warehouse location
- Resolves issue to resume order

### Customer
- Receives order status updates
- Views delivery tracking
- Sees delivery chain: registered → ready → assigned → picked up → sorting → delivery

### External Systems
- **Warehouse System** — provides stock, locations, reservations, stock change notifications
- **Delivery Company** — receives parcel registration, sends tracking updates

## Key Calculations / Decisions

| Name | Trigger | Inputs | Output |
|------|---------|--------|--------|
| **Pick Route Optimization** | order assignment | order items + warehouse layout | optimized walking path |
| **Short-term Reservation** | pick start | product + quantity + location | reservation confirmation / timeout |
| **Delivery Tracking** | delivery company update | parcel ID + status | order state updated |
| **Issue Classification** | issue report | type (lost, damaged, wrong location) | order on hold + issue dashboard entry |
| **Order Status** | any event | picks, packs, issues, delivery updates | current status (pending, picking, packing, ready, shipped, delivered) |

## Artifacts

- **Order** — immutable from checkout. Contains: customer, items, delivery, payment
- **Pick List** — optimized items + warehouse locations. Produced by system for warehouse employee
- **Packed Confirmation** — per item position. Contains: product, quantity, scan timestamp
- **Goods Issue Note (WZ)** — generated by **warehouse system** upon pack confirmation. Our system sends pack event → warehouse system generates WZ. Structure: document_number ("WZ {seq}/{month}/{year}"), issue_date, issue_location, 3 parties (seller/buyer/recipient), line_items (net/gross/VAT per line), summary, signatures (issued_by/received_by), related_documents (FV reference), remarks, footer. Details in `spec/goods-issue-note.json`.
- **Consignment Note** — delivery company document. Generated by carrier system after parcel registration. Contains: carrier (branch, department_code, phones), sender, recipient (name masked for privacy), parcel_details (package_number, total_packages, weight), privacy_notice (RODO). Details in `spec/consignment-note.json`.
- **Delivery Tracking Events** — delivery company updates. Contains: parcel ID, status, location
- **Issue Dashboard** — read model of current issues on warehouse

## In Scope

- Order list with status and assignment
- Order assignment (guarded, one employee at a time)
- Pick list generation (optimized route)
- Short-term reservation during picking
- Pick confirmation (scan)
- Pack confirmation
- Parcel registration with delivery company
- Mark ready for delivery
- Delivery status updates (webhook/polling)
- Order status tracking
- Issue reporting
- Issue dashboard
- Pack event emission → triggers WZ generation in warehouse system (WZ format: `spec/goods-issue-note.json`)
- Consignment Note generation (by carrier system, format: `spec/consignment-note.json`)
- Warehouse integration (stock, locations, reservations)
- Delivery company integration
- Domain model with unit tests
- Hexagonal vertical slice (fulfillment-service)
- API controller fulfilling contract
- Event publishing (order status changes)
- NoSQL persistence

## Out of Scope

- Warehouse layout management (assumed in warehouse system)
- Pick route optimization algorithm (v1: basic zone-based)
- Real-time stock synchronization (v1: periodic updates)
- Multiple carriers (v1: one carrier)
- Return / reverse logistics
- Order modification (v1: immutable, manual handling only)
- Packing material optimization
- Inventory management (stock levels, restocking)
- Warehouse automation (robotics, conveyor)
- Product catalog management (in Product Catalog)
- Shopping / checkout (in Shopping)
- Payment processing (in Shopping)
- Customer notifications (in Shopping)

## Open Questions

- Warehouse layout: is it in our system or warehouse API? How do we get warehouse structure?
- Pick route optimization: is this our system or warehouse API? What algorithm?
- Short-term reservation: duration (10 min? 30 min?), auto-release on timeout?
- Carrier integration: webhook or polling? (v1: one carrier, DPD, wireframe shows future multi-carrier)
- Issue resolution: who resolves? What is the resolution workflow?
- Order on hold: does it block delivery? Can it be cancelled? How does it resume?
- Order numbering: how does it relate to delivery number? Vendor ID?
- Employee authentication: who is an employee? How do we identify warehouse users?
- Pick list format: digital on screen, printable, or handheld scanner?
- Scan data: barcode, QR code, or other?
- Stock mismatch: system says 2 but warehouse has 0. How do we reconcile?

# Fulfillment — Gherkin Scenarios

```gherkin
Feature: Order Assignment
  As a warehouse employee
  I want to assign myself to orders
  So that two employees don't accidentally process the same order

  Scenario: Assign to order
    Given an order "O1" has status "PENDING"
    When employee "E1" assigns to order "O1"
    Then the order is assigned to "E1"
    And the order status is "ASSIGNED"

  Scenario: Prevent double assignment
    Given order "O1" is assigned to "E1"
    When employee "E2" tries to assign to order "O1"
    Then the assignment is rejected
    And the error is "ORDER_ALREADY_ASSIGNED"

Feature: Picking
  As a warehouse employee
  I want to pick items in an optimized order
  So that I can efficiently collect all products

  Scenario: Generate pick list
    Given an order "O1" is assigned to "E1"
    When the employee requests the pick list
    Then an optimized pick list is generated
    And each item shows warehouse locations

  Scenario: Reserve picked items
    Given a pick list shows item "75423" at location "A-12-3"
    When the employee starts picking item "75423"
    Then the product is reserved
    And the reservation has a timeout

  Scenario: Confirm pick
    Given item "75423" is reserved
    When the employee scans the product
    Then the item is marked as picked
    And the reservation is released

  Scenario: Pick with timeout
    Given a reservation is made for item "75423"
    When the reservation expires
    Then the reservation is released
    And the item is available for other employees

Feature: Packing and Shipping
  As a warehouse employee
  I want to pack items and register the parcel
  So that the order can be shipped

  Scenario: Mark packed
    Given all items in order "O1" are picked
    When the employee marks the order as packed
    Then the order status is "PACKED"
    And the goods issue note is generated

  Scenario: Register parcel
    Given order "O1" is packed
    When the system registers the parcel with carrier "DPD"
    Then a delivery number is assigned
    And the order status is "REGISTERED"

  Scenario: Mark ready for delivery
    Given order "O1" has a delivery number
    When the employee marks it ready for delivery
    Then the order status is "READY_FOR_DELIVERY"
    And the delivery company is notified

Feature: Delivery Tracking
  As a customer
  I want to see the delivery status
  So that I know when my order will arrive

  Scenario: Track delivery status
    Given order "O1" has delivery number "D123"
    When the carrier updates status to "PICKED_UP"
    Then the order delivery status is "PICKED_UP"
    And the customer can see the update

  Scenario: Full delivery chain
    Given order "O1" has delivery number "D123"
    When the carrier updates through the chain:
      | status |
      | REGISTERED |
      | READY |
      | ASSIGNED |
      | PICKED_UP |
      | SORTING |
      | DELIVERED |
    Then each status is recorded
    And the final status is "DELIVERED"

Feature: Issue Handling
  As a warehouse employee
  I want to report issues when things go wrong
  So that the order can be handled correctly

  Scenario: Report lost item
    Given order "O1" has item "75423" quantity 2
    When the employee cannot find item "75423"
    And the employee reports issue "LOST"
    Then the order is put on hold
    And an issue is added to the dashboard

  Scenario: Resolve issue
    Given order "O1" has an open issue "LOST"
    When the issue resolver finds the missing item
    And the issue is marked as resolved
    Then the order resumes from "ON_HOLD"
    And the pick list is updated

  Scenario: Issue dashboard
    Given there are 3 open issues
    When the operations manager views the issue dashboard
    Then all 3 issues are displayed
    And each issue shows type, order, product, and status

Feature: Search & Filter Orders
  As a warehouse employee
  I want to search and filter orders
  So that I can find specific orders quickly

  Scenario: Filter by status
    Given there are orders in different statuses
    When the employee filters by status "ON_HOLD"
    Then only "ON_HOLD" orders are shown

  Scenario: Search by order number
    Given there are multiple orders
    When the employee searches for "ORD-0042"
    Then only "ORD-0042" is returned

Feature: Issue Resolution
  As an issue resolver
  I want to resolve warehouse issues
  So that the order can continue processing

  Scenario: Resolve issue and resume order
    Given order "O1" has an open issue "LOST"
    When the issue resolver finds the missing item
    And the issue is resolved
    Then the order status changes from "ON_HOLD" to "PICKING"
    And the pick list is updated
```
